## Ask a question or share an idea

[GitHub Discussions](https://github.com/chriscasper/startica/discussions) is the place for questions, ideas, and showing how you use Startica. Search there first; someone may have asked already.

## Report a bug

Open an [issue on GitHub](https://github.com/chriscasper/startica/issues/new/choose). Include your operating system, the Startica version or commit, what you expected, what happened, and any error text from the terminal or the **System** page.

## Report a security problem

Please don't open a public issue. Follow the [security policy](https://github.com/chriscasper/startica/blob/main/SECURITY.md): email security@mystartica.com or use GitHub's private vulnerability reporting.

## Contribute

Code, docs, and testing on Windows and Linux are all welcome. The [contributing guide](https://docs.mystartica.com/contributing) covers the architecture, development setup, and the checks every pull request must pass. Good places to start:

- Issues labelled [good first issue](https://github.com/chriscasper/startica/issues?q=is%3Aopen+label%3A%22good+first+issue%22)
- [Add a channel adapter](https://docs.mystartica.com/contributing/channel-adapter) for a community platform
- [Add a metrics connector](https://docs.mystartica.com/contributing/connector) for another analytics or billing tool
- Add an accessibility, search or security check (see the [architecture](https://docs.mystartica.com/contributing/architecture) for where checks live)
- [Add a playbook](https://docs.mystartica.com/contributing/playbook) from your own growth experience
- Fix or improve a [docs page](https://docs.mystartica.com/contributing/docs-and-website)

For larger changes, open a discussion first so we can agree on the approach before you write the code.
